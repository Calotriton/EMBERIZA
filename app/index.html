Working

bacpipe, in a browser tab

See how a model hears your recordings.

EMBERIZA runs bacpipe's own code on this computer. It turns each few seconds of sound into an embedding with Perch 2.0 or BirdNET+ V3.0, then maps, clusters and probes those embeddings. There is nothing to install and nothing is uploaded.

  • bacpipe's results. bacpipe's own code makes the result files. The embeddings agree with bacpipe's to within 0.00001.
  • Every bacpipe option. Both configuration files are on the left, with bacpipe's defaults.
  • Results you can take with you. One ZIP in bacpipe's folder layout, which bacpipe itself can open.

      About EMBERIZA

      Embedding Maps for Bacpipe: Explore Recordings In a Zero-install App. Emberiza is the genus of the buntings.

      What runs here

      The analysis is bacpipe : its Python files, unchanged, running in this tab with Pyodide. Two things are done differently, because a browser cannot do them bacpipe's way:

      • The neural networks run in ONNX Runtime Web, from the same model files bacpipe downloads.
      • The plots are drawn by this page, from bacpipe's result files, instead of by bacpipe's own dashboard. bacpipe's picture files (PNG) are not made.

      How close to bacpipe

      Checked against bacpipe 1.3.5 on recordings at 32 and 48 kHz, mono and stereo:

      • The audio windows fed to the networks are identical. With ONNX Runtime on a processor, the embeddings, metadata.yml and the labels are identical too.
      • In this browser the embeddings and the confidence scores agree with bacpipe's to within 0.00001. bacpipe's Raven tables write the confidence times the sample rate as "High Freq (Hz)", so there the same difference reads as a few hundredths of a hertz.
      • UMAP maps are not the same picture. umap-learn cannot run in a browser, so EMBERIZA has its own copy of the method. It builds the same neighbour graph, and from the same start it ends at the same positions. But the start is computed by another version of SciPy, and umap-learn draws its random numbers from the start's last digits, so the final positions differ. The maps keep neighbours as well as bacpipe's. PCA is the same map.
      • k-means and the linear probe start from unseeded random numbers in bacpipe, so their scores change from run to run in bacpipe too.
      • On Windows, bacpipe 1.3.5 puts the "default classifier" label on the wrong windows when recordings are in sub-folders, because it sorts paths written with "\" and "/" together. EMBERIZA writes paths with "/", as on Linux, and its labels line up with the windows.
      • Apart from that label, the kNN probe and every clustering score without k-means are the same as bacpipe's.

      Not available here

      • bacpipe's other 25 models. They need PyTorch or TensorFlow.
      • Recordings longer than the browser's memory allows. A whole recording is read at once, as bacpipe does.
